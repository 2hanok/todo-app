## 3. 표준화 (다음 버전에 적용)

1. 이슈 처리 흐름: 검토(수락/보류/거절 라벨 + 판단 근거 코멘트) → `docs/pdca/vX/01-plan.md` → 이슈 본문에 계획 링크·요구사항 체크리스트 → 개발 → `03-check.md` → 배포 → `04-act.md` → 이슈 종료.
2. 라벨: `수락`·`보류`·`거절`(판정) + `bug`·`enhancement`·`documentation`(유형) + 버전 라벨(`v1.1`).
3. 배포 검증: push 후 운영 URL에서 `<meta name="version">`과 핵심 시나리오를 재확인한다.
4. 날짜는 항상 `localDateStr()`을 쓰고 `toISOString()`으로 날짜 문자열을 만들지 않는다.
